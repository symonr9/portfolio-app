# Portfolio Improvement Research

1. Treat the task as report-only unless implementation is explicit.
2. Read project guidance and inspect relevant routes, content models, presentation, and current capabilities.
3. Browse current primary or authoritative sources appropriate to the question, such as official framework docs, W3C/WAI, web.dev, reputable career centers, platform docs, and direct competitor product pages.
4. Distinguish sourced guidance, site observations, and inference. Cite claims close to sources.
5. Evaluate recommendations against Contentful-managed content, Next.js on Netlify, career-agnostic architecture, accessibility, maintainability, privacy, and actual site state.
6. Avoid proposing features the project already has. Separate prerequisite content work from engineering.
7. Rank recommendations by user or employer value, effort, risk, and dependency.
8. Surface decisions only when alternatives materially change scope, architecture, privacy, recurring cost, or UX.

Lead with the consequential finding. Provide priorities, evidence and gap, sequencing, major decisions, and an implementation prompt when requested. Do not edit files in report-only mode.
